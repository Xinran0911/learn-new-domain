# Learning Output Quality Checklist

Use before finalizing a large learning artifact.

## Source Quality

- [ ] Source map exists.
- [ ] Official or primary sources are identified where available.
- [ ] Source status is marked: verified, user-provided, unverified lead, or rejected.
- [ ] No fabricated source, quote, metric, date, author, or link is present.
- [ ] Version-sensitive facts are verified or marked uncertain.

## Structure

- [ ] The output starts with learning goal and domain boundary.
- [ ] It follows a top-down path before details.
- [ ] Categories are mostly MECE.
- [ ] There is a clear sequence or decision logic.
- [ ] Raw notes are separated from final synthesis.

## Practicality

- [ ] Includes examples.
- [ ] Includes a checklist, template, or playbook.
- [ ] Explains what good looks like.
- [ ] Explains common mistakes.
- [ ] Invites user follow-up and refinement.

## Reuse

- [ ] The result can become a note, tutorial, Skill, or workflow.
- [ ] Key terms and source links are preserved.
- [ ] Open questions and weak assumptions are explicit.
- [ ] User has been asked whether to package the result as a Skill.
